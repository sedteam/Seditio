# Глава 11. Локализация и интернационализация (i18n)

В этой главе рассматривается устройство мультиязычности (интернационализации) в Seditio CMS, правила расположения и структура языковых файлов ядра, модулей, плагинов и тем оформления, а также логика автоподгрузки и переопределения локализаций.

---

## 11.1. Мультиязычность в Seditio CMS

Seditio CMS изначально проектировалась с возможностью гибкой поддержки нескольких языков как для интерфейса (панели управления, системных сообщений, тем оформления), так и для элементов структуры (категорий страниц и разделов форума).

### 11.1.1. Определение активного языка
Язык интерфейса для каждого конкретного посетителя определяется во время загрузки страницы в ядре системы:
* **Для зарегистрированных пользователей:** Язык считывается из профиля пользователя (поле `user_lang` в БД) и записывается в переменную `$usr['lang']`.
* **Для гостей:** Используется значение по умолчанию из глобального конфигурационного файла (`datas/config.php`), хранящееся в `$cfg['defaultlang']` (по умолчанию обычно `'en'` или `'ru'`).
* **Окончательный выбор:** Выбранный двухсимвольный код языка (например, `'ru'`, `'en'`, `'tr'`) записывается в глобальную переменную `$lang`, которая используется во всех последующих вызовах локализации.

### 11.1.2. Локализация структуры сайта и контента страниц (Плагин i18n)
Для полноценной поддержки мультиязычного контента в Seditio 186 входит специализированный плагин **i18n**:
* **Мультиязычность контента страниц:** Плагин позволяет переводить все текстовые поля страниц (`title`, `desc`, `text`, `text2`) и все SEO-метаданные (`seo_title`, `seo_desc`, `seo_keywords`, `seo_h1`) на заданные языки без дублирования записей в основной таблице страниц. Переводы хранятся в отдельной таблице `sed_i18n_pages`.
* **Мультиязычность категорий:** В структуре разделов (`sed_structure`) переводы названий и описаний категорий сохраняются в таблице `sed_i18n_structure`.
* **Вкладки перевода в шаблонах:** В формах добавления/редактирования страниц и категорий выводятся языковые вкладки с помощью тегов:
  - `{PAGEADD_I18N_TABS_HEADERS}` и `{PAGEADD_I18N_TABS_BODY}` — в `page.add.tpl`.
  - `{PAGEEDIT_I18N_TABS_HEADERS}` и `{PAGEEDIT_I18N_TABS_BODY}` — в `page.edit.tpl`.
  - `{STRUCTURE_UPDATE_I18N_TABS_HEADERS}` и `{STRUCTURE_UPDATE_I18N_TABS_BODY}` — в форме редактирования структуры.
* **Переключатель языков (`{HEADER_I18N_SELECTOR}`):** В шаблоне шапки (`header.tpl`) тег `{HEADER_I18N_SELECTOR}` генерирует ссылки на переключение языка сайта с автоматическим сокрытием текущего активного языка.
* **Автоматический Fallback:** Если перевод страницы или категории для выбранного языка отсутствует, ядро автоматически отображает контент на основном языке сайта (`$cfg['defaultlang']`).

## 11.2. Файловая структура языковых пакетов ядра

Все языковые пакеты для ядра Seditio CMS располагаются в системном каталоге `/system/lang/`.

### 11.2.1. Каталоги языков
Внутри `/system/lang/` для каждого языка создается отдельная подпапка с двухсимвольным кодом (ISO 639-1):
* `/system/lang/en/` — английский пакет.
* `/system/lang/ru/` — русский пакет.
* `/system/lang/tr/` — турецкий пакет.

### 11.2.2. Состав языкового пакета ядра
Внутри папки каждого языка находятся три основных файла:
1. **`main.lang.php`** — содержит локализацию публичной части сайта (кнопки, заголовки, тексты форм, даты, разметка прав доступа). Все фразы записываются в глобальный массив `$L` (например, `$L['Home'] = "Главная";`).
2. **`admin.lang.php`** — локализация административной зоны управления. Используется только в панели управления (`SED_ADMIN`) и заполняет массив фраз администрирования.
3. **`message.lang.php`** — локализация системных предупреждений, ошибок и уведомлений (например, сообщения об успешном добавлении, ошибки валидации форм, ошибки ЧПУ, ошибки 404).

## 11.3. Локализация модулей и плагинов

Каждый дополнительный модуль и плагин в Seditio является автономным компонентом и содержит собственные файлы локализации.

### 11.3.1. Размещение языковых файлов
* **Модули:** Файлы локализации модуля располагаются в его папке по пути:
  `/modules/{код_модуля}/lang/{код_модуля}.{код_языка}.lang.php`
  *Пример:* `/modules/page/lang/page.ru.lang.php` — файл русской локализации модуля Страниц.
* **Плагины:** Файлы локализации плагина располагаются в его папке по пути:
  `/plugins/{код_плагина}/lang/{код_плагина}.{код_языка}.lang.php`
  *Пример:* `/plugins/recentitems/lang/recentitems.ru.lang.php` — файл русской локализации плагина RecentItems.

### 11.3.2. Локализация конфигураций (Префикс `cfg_`)
Seditio CMS использует файлы локализации модулей и плагинов для перевода названий и описаний настроек, выводимых в административной панели.
Если модуль или плагин имеет зарегистрированную настройку (например, `maxpages` в плагине `recentitems`), то для её перевода в языковом файле объявляется элемент массива с префиксом `cfg_`:
```php
$L['cfg_maxpages'] = array("Количество страниц", "Укажите максимальное количество страниц для вывода в блоке");
```
* **Первый элемент массива** — человекочитаемое краткое название настройки.
* **Второй элемент массива** — подробное всплывающее описание/подсказка к этой настройке.

### 11.3.3. Локализация интерфейса компонента
Все прочие строки, необходимые для работы контроллера или вывода в TPL-шаблонах компонента, записываются в глобальный массив `$L` с уникальными префиксами во избежание коллизий:
```php
$L['pag_titletooshort'] = "Заголовок слишком короткий либо отсутствует";
$L['lis_submitnew'] = "Добавить новую запись";
```

## 11.4. Механизм поиска и загрузки языков (sed_langfile)

Для корректного подключения файлов локализации используется системная функция `sed_langfile()` из файла `system/functions.php`.

### 11.4.1. Сигнатура функции
```php
function sed_langfile($code, $type = 'plugin', $lang = null)
```
* **`$code`** (string) — уникальный код компонента (код плагина или модуля).
* **`$type`** (string, необязательный) — тип компонента (`'plugin'` или `'module'`). По умолчанию — `'plugin'`.
* **`$lang`** (string, необязательный) — принудительно запрашиваемый язык. Если не указан, берется активный язык посетителя `$usr['lang']` или дефолтный `$cfg['defaultlang']`.

### 11.4.2. Алгоритм поиска и резервная логика (Fallback)
Функция выполняет поиск файла на диске по следующим приоритетам:
1. **Основной язык:** Ищется файл по выбранному языку. Например, для плагина `myplugin` при русском языке пользователя путь будет: `/plugins/myplugin/lang/myplugin.ru.lang.php`.
2. **Английский резервный вариант (Fallback):** Если основной файл локализации не найден (например, у пользователя выбран французский язык `'fr'`, а для плагина есть только английский), система ищет английскую локализацию: `/plugins/myplugin/lang/myplugin.en.lang.php`.
3. **Результат:** Функция возвращает абсолютный путь к существующему файлу на диске или пустую строку, если локализаций не найдено.

Пример подключения в коде плагина:
```php
$langfile = sed_langfile('myplugin', 'plugin');
if (!empty($langfile)) {
    require($langfile);
}
```

## 11.5. Последовательность инициализации языков при загрузке страницы

Инициализация языкового окружения происходит на этапе первоначальной загрузки ядра в системном файле `system/common.php`. Подключение файлов строго упорядочено:

### 11.5.1. Загрузка ядра локализации
Сначала подключается основной системный языковой файл:
```php
$mlang = SED_ROOT . '/system/lang/' . $usr['lang'] . '/main.lang.php';
// ...
require($mlang);
```
После этого становятся доступны базовые массивы локализации сайта (например, даты, служебные слова, базовые заголовки).

### 11.5.2. Автоматическая загрузка языков активных модулей
Для того чтобы общие строки модулей (такие как названия категорий, префиксы заголовков страниц `$L['core_page']` и т.д.) были доступны глобально (например, при рендеринге меню в шапке или виджетов в подвале), ядро перебирает массив активных модулей `$sed_modules` и подключает их языковые файлы:
```php
foreach ($sed_modules as $mod_code => $mod_row) {
    if ($mod_lang_file = sed_langfile($mod_code, 'module', $lang)) {
        include_once($mod_lang_file);
    }
}
```

### 11.5.3. Глобальная загрузка системных сообщений (message.lang.php)
В версии 186 системный файл сообщений `message.lang.php` подключается глобально на этапе инициализации ядра в `system/common.php`:
```php
$msg_lang_file = SED_ROOT . '/system/lang/' . $usr['lang'] . '/message.lang.php';
if (file_exists($msg_lang_file)) {
    include_once($msg_lang_file);
}
```
Благодаря этому системный массив `$L['msg...']` (сообщения об ошибках, уведомления об авторизации, информационные оповещения) доступен повсеместно во всех модулях, плагинах и XTemplate-шаблонах без необходимости ручного вызова или повторного подключения.

### 11.5.4. Переопределение строк на уровне скина (темы оформления)
Наивысшим приоритетом локализации обладает активный скин сайта. После загрузки всех системных файлов и файлов модулей ядро проверяет наличие языкового файла внутри папки темы (например, `skins/sympfy/sympfy.ru.lang.php`):
```php
if (@file_exists($usr['skin_lang'])) {
    require($usr['skin_lang']);
}
```
Благодаря этому верстальщик может переопределить любую языковую строку ядра или модулей (массив `$skinlang`) непосредственно на уровне активной темы оформления без вмешательства в исходные PHP-файлы системы.

## 11.6. Практическое руководство по созданию мультиязычного плагина

Создадим файлы локализации для плагина с кодовым именем `myplugin`, имеющего одну текстовую настройку `banner_text`.

### 11.6.1. Создание папки языков
Внутри каталога `/plugins/myplugin/` создайте подпапку `lang/`. В ней создайте два файла: `myplugin.en.lang.php` (английский язык) и `myplugin.ru.lang.php` (русский язык).

### 11.6.2. Создание английского файла `myplugin.en.lang.php`
```php
<?php
/* ====================
[BEGIN_SED]
File=plugins/myplugin/lang/myplugin.en.lang.php
Version=1.0.0
Updated=2026-jul-06
Type=Plugin.lang
Name=My Plugin (English Localization)
[END_SED]
==================== */

if (!defined('SED_CODE')) exit();

// Перевод настроек плагина в админ-панели
$L['cfg_banner_text'] = array("Banner html text", "Enter the text or HTML markup to display in the header banner.");

// Строки вывода в пользовательской части
$L['myplug_welcome'] = "Welcome to our website!";
$L['myplug_readmore'] = "Read more";
```

### 11.6.3. Создание русского файла `myplugin.ru.lang.php`
```php
<?php
/* ====================
[BEGIN_SED]
File=plugins/myplugin/lang/myplugin.ru.lang.php
Version=1.0.0
Updated=2026-jul-06
Type=Plugin.lang
Name=My Plugin (Russian Localization)
[END_SED]
==================== */

if (!defined('SED_CODE')) exit();

// Перевод настроек плагина в админ-панели
$L['cfg_banner_text'] = array("HTML текст баннера", "Введите текст или HTML-разметку для отображения в баннере шапки.");

// Строки вывода в пользовательской части
$L['myplug_welcome'] = "Добро пожаловать на наш сайт!";
$L['myplug_readmore'] = "Читать далее";
```

### 11.6.4. Использование в PHP-коде плагина (`myplugin.php`)
```php
<?php
if (!defined('SED_CODE')) exit();

// Подключаем языковой файл (сработает автовыбор языка или fallback на .en.)
$langfile = sed_langfile('myplugin', 'plugin');
if (!empty($langfile)) {
    require($langfile);
}

// Рендерим шаблон (нет необходимости передавать строки $L в шаблонизатор вручную)
$t->parse("MAIN");
$t->out("MAIN");
```

> [!NOTE]
> **Автоматическая vs Ручная загрузка языковых файлов плагинов:**
> * **Автоматическая:** Ядро Seditio самостоятельно находит и подключает языковой файл плагина при обращении к его автономным разделам (`standalone`, `popup`), а также при выводе его настроек в административной панели управления. В этих исполняемых файлах повторно вызывать `sed_langfile()` не требуется.
> * **Ручная:** Во всех остальных частях-обработчиках хуков (например, `index.tags`, `header.tags`, `users.register.add.first` и т.д.) ядро не загружает языки плагина автоматически. Разработчик обязан подключать локализацию вручную с помощью конструкции: `if ($f = sed_langfile('код_плагина', 'plugin')) { require($f); }`.

> [!TIP]
> **Исключение избыточного вызова `assign`:**
> В Seditio CMS нет необходимости принудительно регистрировать каждую языковую строку плагина в шаблонизаторе с помощью метода `$t->assign()`. Поскольку шаблонизатор поддерживает префикс глобального контекста `PHP.`, любые языковые фразы из массива `$L` (после подключения языкового файла) доступны напрямую в TPL-шаблоне через синтаксис `{PHP.L.имя_переменной}`. Это делает PHP-код плагина чистым и лаконичным.

### 11.6.5. Использование в TPL-шаблоне плагина (`myplugin.tpl`)
```html
<!-- BEGIN: MAIN -->
<div class="welcome-banner">
    <h2>{PHP.L.myplug_welcome}</h2>
    <p>{PHP.cfg.plugin.myplugin.banner_text}</p>
    <a href="index.php?module=page" class="btn">{PHP.L.myplug_readmore}</a>
</div>
<!-- END: MAIN -->
```
При открытии страницы гостем с русским языком шаблонизатор автоматически выведет надпись *"Добро пожаловать на наш сайт!"*, а для англоязычного гостя — *"Welcome to our website!"*, считывая значения напрямую из глобального массива `$L`.

## 11.7. Единая система динамических переводов и компилируемый кэш (Seditio 186)

В Seditio 186 реализована современная централизованная система управления переводами, объединяющая языковые строки ядра, активных модулей, плагинов и тем оформления в единый управляемый репозиторий с высокоскоростным компилируемым PHP-кэшем.

### 11.7.1. Архитектура хранения в базе данных
Система опирается на две таблицы ядра:
1. **`sed_languages`** — реестр установленных и активных языков сайта:
   * `lang_code` (varchar 16, PK) — двухбуквенный или составной код языка (например, `ru`, `en`, `tr`, `kz`).
   * `lang_title` / `lang_native` — международное и нативное название языка (например, `Russian` / `Русский`).
   * `lang_direction` — направление письма (`ltr` слева направо или `rtl` справа налево).
   * `lang_active` — статус активности языка (`1` — активен, `0` — отключен).
   * `lang_order` — порядок сортировки в селекторах интерфейса.
2. **`sed_translations`** — централизованный банк всех языковых переменных:
   * `tra_lang` — код языка (`ru`, `en`, ...).
   * `tra_scope` — область принадлежности (`core`, `module`, `plugin`, `skin`).
   * `tra_code` — код компонента (`main`, `admin`, `page`, `comments`, `sympfy`).
   * `tra_key` — ключ переменной в массиве `$L` (например, `Home`, `statistics_title`, `cfg_maxstars`).
   * `tra_val` — переведенное текстовое значение.
   * `tra_type` — тип записи: `1` — системный перевод (импортирован из дистрибутива), `0` — пользовательская правка/переменная (создана или изменена администратором).
   * `tra_order` — весовой приоритет наложения при компиляции словаря (100 — ядро, 200 — модули, 300 — плагины, 400 — скины).
   * `tra_updated` — временная метка последнего изменения.
   * *Уникальный ключ `tra_unique (tra_lang, tra_key, tra_scope, tra_code)`* исключает дублирование записей внутри одного компонента.

### 11.7.2. Компилируемый PHP-кэш (`datas/cache/sed_lang.*.php`)
Для достижения максимальной производительности система не выполняет SQL-запросы к таблице `sed_translations` при отображении страниц сайта:
* Все активные переводы компилируются функцией `sed_translations_generate()` в единые плоские PHP-файлы: `datas/cache/sed_lang.{код_языка}.php`.
* Внутри кэш-файла формируется оптимизированный единый массив `$L`, подключаемый за одну операцию `require` в `system/common.php`.
* Скорость доступа к любым языковым фразам ядра, модулей и плагинов эквивалентна прямому обращению к оперативной памяти (O(1)), с нулевой нагрузкой на СУБД.

### 11.7.3. Манифест-флаг `Translations=1` и изоляция расширений
Для того чтобы языковые файлы сторонних или устаревших плагинов не засоряли центральную базу данных и не перезаписывали системные переменные ядра, в заголовке `[BEGIN_SED]` языковых файлов введен флаг:
```text
Translations=1
```
* **Штатные модули и плагины Seditio** содержат данный флаг: их переводы импортируются в БД при установке/обновлении и попадают в общий скомпилированный кэш.
* **Сторонние и устаревшие плагины (без флага `Translations=1`)** изолируются: они не попадают в БД, а функция `sed_langfile()` автоматически возвращает путь к локальному `.lang.php` файлу для локального runtime-подключения через `require_once`. Это предотвращает коллизии неспецифических ключей (например, устаревших `$L['plu_title']`).

### 11.7.4. Панель управления переводами (`admin.php?m=translations`)
Управление переводами вынесено в специализированный раздел панели администратора:
* **Навигатор и поиск:** Полнотекстовый поиск по ключам и значениям, фильтрация по языкам, областям (`core`, `module`, `plugin`, `skin`) и типам (системные / пользовательские).
* **Редактирование в реальном времени:** Изменение любых текстов сайта прямо из браузера без ручного редактирования PHP-файлов. При редактировании системной строки запись автоматически переводится в категорию пользовательских (`tra_type = 0`), что защищает ее от случайного затирания при обновлениях.
* **Управление языками:** Добавление новых языков, клонирование существующих пакетов, переключение активности и настройка направления текста (LTR / RTL).
* **Импорт и экспорт (JSON):** Экспорт языкового пакета в структурированный JSON-файл для передачи переводчикам и импорт с выбором стратегии слияния:
  * *Обновить существующие и добавить новые* (рекомендуется).
  * *Только добавить отсутствующие*.
  * *Полная замена языка*.
* **Инструменты обслуживания (`s=tools`):**
  * *Скомпилировать кэш языков:* пересборка всех кэш-файлов `sed_lang.*.php` из базы данных.
  * *Импортировать недостающие:* мягкое добавление новых системных переменных из файлов дистрибутива без изменения существующих текстов.
  * *Полный реимпорт из файлов:* сброс всех системных строк (`tra_type = 1`) для дисковых языков к заводским значениям с сохранением всех кастомных переменных администратора (`tra_type = 0`) и языков без локальных файлов.
